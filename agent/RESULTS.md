# finews LangGraph agent — 实验记录

逐步记录每一步搭了什么、对应哪个 agent 模式、跑出什么结果（含诚实的局限）。
六步跑完后据此做整体讲解。代码在 `agent/`，独立 Python LangGraph，本地跑，
只读复用同一个 Supabase 概念库。

## 控制流图

```
START → prepare → agent ⇄ tools → draft → critic ⇄ revise → END
```
- `agent ⇄ tools`：工具循环，模型自己决定搜不搜/查不查、搜什么、几次，上限 4 轮
- `critic ⇄ revise`：自检回改循环，上限 1 次
- 控制流（要不要搜、改没改好）由模型在条件边上决定；边界和上限由图声明式画死

## Step 0 — 脚手架 + 连通性（基础设施，非模式）

- 建 `agent/` 子项目、venv、装 langgraph / langchain-openai / psycopg 等。
- 连通性自检 3/3：DeepSeek（flash/pro）、Supabase 概念库、Tavily。
- 概念库现有 **37 条**概念（Step 2 做 RAG 的检索基线）。

## Step 1 — 工具使用 Tool Use

- 给 agent 一个 search 工具（Tavily），模型自主决定调用；定稿单独不带工具、出干净 JSON（两阶段）。
- 验证（sample 5 汇金股份）：flash 自主搜 **3 次**、收 **15 条**来源，出合法四段 JSON + 3 概念，机制段用上了搜来的政策/营收数字。
- 要点：搜不搜/搜什么/几次全由模型决定，代码只画"可搜"+"最多 4 轮"。这是 agent 和普通一次性调用的分界。

## Step 2 — 检索增强 / 记忆 RAG

- 加第二个工具 concept_lookup（查自己的概念库）+ 把概念清单注入 system prompt。
- 验证（sample 5）：concept_lookup 命中 **5 次**，输出概念复用 **3/3**（Step 1 无 RAG 时是 2/3、且含 1 个自造名）。
- 亮点：复用了"分子端"——从别的估值类新闻攒下的概念，被用到这条并购新闻，跨新闻把概念连成网。
- 取舍：库才 37 条，注入清单 + 精确查名就够，没上向量库（够用不上重武器）。

## Step 3 — 反思 Reflection

- 出稿后加 critic（按规则审）+ revise（按问题改）回改循环，上限 1 次。
- 验证（sample 4 证监会）：草稿写"投保基金 C 类 2.5%–3.5%"，自检对照搜来的来源发现 **3.5% 应为 3%**（3.5% 属 D 类），标问题 → 回改成 2.5%–3% → 再审通过。一次跑里 critic 两条分支都走了（不过→改、过→结束）。
- 局限：自检挡得住"跟给定来源对不上"，挡不住"来源本身错 / 越界补料"（如搜来的"前 20 扩前 30"存疑说法没被挡）。reflection 不是免费的正确性保险。

## Step 4 — 评测 + 可观测（评测骨架）

- `eval/`：解析 6 条固定样本 → 跑完整 agent → 算 3 个确定性指标 → 落 `runs/*.json`，可跨 run 比。
- 指标：搜索可溯源数据点（工具）、概念复用率（RAG）、首检通过率（反思）。

### Baseline（2026-05-31，完整原文，三项全开）

| 样本 | 搜索 | 搜索可溯源 | 疑似编造 | 概念复用 | 首检 |
|---|---|---|---|---|---|
| 1 降准 | 0 | 0 | 1\* | 1/3 | 挂→回改后过 |
| 2 PMI | 1 | 4 | 0 | 2/3 | 过 |
| 3 CPI | 3 | 3 | 0 | 0/3 | 过 |
| 4 证监会 | 1 | 0 | 0 | 0/3 | 过 |
| 5 汇金 | 4 | 1 | 0 | 2/3 | 过 |
| 6 中美 | 3 | 0 | 0 | 0/3 | 过 |

聚合：首检通过 **5/6**（回改后 6/6）；概念复用 **5/18**（0.28）；搜索可溯源均 **1.33**；疑似编造均 0.17。
存档：`agent/eval/runs/20260531T155224Z_baseline.json`

### 诚实发现（这些比数字本身值钱）

- 自检有效：唯一首检挂的样本 1，回改后过。
- "疑似编造 150亿"（\*）是指标误报，不是模型编：原文"150**至200**亿元"，模型写"150亿"没错，子串精确匹配被中间的"至200"挡住 → Step 5 加 LLM 裁判复核边界数字。
- 搜索可溯源仅 1.33（PROJECT.md 是 5）：因为喂的是完整原文、数字本就在原文里，搜索没多少新东西可补 → 要量搜索增量需截断输入造信息缺口 → Step 5 加截断条件。
- 复用率 0.28：库里有的主题（PMI / 并购）复用高，全新主题（CPI / 证监会 / 中美）为 0；RAG 价值取决于库覆盖。
- 元教训（PM 视角）：第一版指标有误报、头条数字受 agent 随机性影响、搜索价值只在信息缺口下显现 → 据此改实验设计。这套"发现问题再改实验"本身就是产出。

## Step 5 — 对照实验 + 可观测

- 给图加配置开关（LangGraph configurable）：开/关搜索、开/关反思；run_eval 加截断输入（仿 PROJECT.md 制造信息缺口，逼出搜索价值）。
- 可观测：`run.py --trace` 用 `graph.stream` 逐节点打印执行轨迹（本地、零配置、不依赖云端）。

### 对照表（截断输入造信息缺口，2026-05-31）

| 条件 | 每篇可溯源数据点 | 疑似编造 | 概念复用率 | 首检通过 |
|---|---|---|---|---|
| 关搜索 (n=6) | **0.0** | 0.0 | 0.36 | 4/6 |
| 开搜索 (n=5) | **4.4** | 0.4 | 0.20 | 5/5 |

- 搜索的价值（头条）：信息不足时，搜索把每篇可溯源数据点从 0 提到约 4-5（复现 PROJECT.md 的"0→5"）。
- 搜索的代价：偶尔采信不准来源，疑似编造 0→0.4。
- 反直觉：开搜索后概念复用率反而降（0.36→0.20）——搜来的内容带出更多新颖/具体概念，不在已有库里。RAG 复用价值取决于库覆盖。
- n 不等：长批量里 Supabase pooler 偶发断连、DeepSeek 偶发空响应丢样本；已加重连 + 普通模式兜底 + 逐样本隔离（单条失败不炸整批）。

### Trace 示例（sample 4，开搜索；`-m agent.run --sample 4 --trace`）

```
prepare → agent(查库×3) → tools(0命中) → agent(搜索×3) → tools(14来源)
→ agent(搜索×2) → tools(23来源) → agent(查库×2) → draft(2概念) → critic(通过)
```
模型自主交替用 concept_lookup(RAG) 和 search(联网)，4 轮工具、5 次搜索、23 来源，自己决定每步要什么——这张轨迹就是"控制流在模型手里"的直接证据。

### 三类外部服务 flakiness 及应对（在不稳基础设施上做稳健 agent）

- DeepSeek json 模式偶发空响应 → 重试 + 退回普通模式 + 容错解析。
- 模型偶尔把响应返成 JSON 标量、把 issue 写成字符串 → parser 加类型兜底。
- Supabase pooler 断开空闲连接 → db 层断线重连。
- 逐样本 try/except：单条失败只跳过，不炸整批。

## 整体小结：4 个模式 × 量化结果

| 模式 | 怎么实现 | 量化结果 |
|---|---|---|
| 工具使用 Tool Use | search 工具 + 模型自主调用循环 | 可溯源数据点 0 → 4.4/篇 |
| RAG / 记忆 | concept_lookup + 概念清单注入 | 命中即复用、跨新闻连网（sample 5 复用 3/3） |
| 反思 Reflection | critic 审 + revise 改回改循环 | 抓到并改对真实数字错（3.5%→3%）；baseline 首检通过 5/6 |
| 评测 + 可观测 | 6 条固定样本 + 确定性指标 + trace | 一键复跑对照表 + 逐节点轨迹 |
